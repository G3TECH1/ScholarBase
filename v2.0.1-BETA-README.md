# ScholarBase v2.0.1 Beta — Technical Architecture & Cloud Migration Guide

This document outlines the technical stack, architectural changes, and deployment strategy for **ScholarBase v2.0.1 Beta**, marking the transition from a local desktop client to a fully online web application platform.

---

## 🏗️ Architectural Overview

Version 2.0.1 completely replaces the local SQLite/Electron architecture with a **Cloud-Native Web Architecture**. All client sessions (Admins, Principals, Teachers) interact directly with cloud API gateways over secure HTTPS/WebSockets.

## 🛠️ Technical Stack

### Frontend Application
- **Framework:** Vanilla JavaScript for User experience.
- **State & Data Fetching:** AJAX and Alpine.js for caching, optimistic UI updates, and real-time backend synchronization.
- **Styling & UI:** Bootstrap CSS with responsive layouts optimized for desktop, tablet, and mobile browsers.

### Backend Infrastructure
- **API Runtime:** Node.js (Express / NestJS) REST & WebSocket server.
- **Database:** PostgreSQL for robust transactional integrity, multi-tenant school schema isolation, and automated point-in-time recovery.
- **Authentication:** OAuth2 / JWT session handling with role-based access control (RBAC) enforcing granular permission layers across Admins, Principals, Teachers, and Parents.
- **Hosting & CDN:** Cloud infrastructure hosted on  DigitalOcean with TLS/SSL encryption end-to-end.

---

## 🔐 Role-Based Access Control (RBAC) Matrix

| Role | Permissions |
| :--- | :--- |
| **Super Admin / Principal** | Full institutional access, audit logging, staff account creation, system configuration, global reporting. |
| **Administrative Staff** | Student enrollment, fee record entries, receipt processing, inventory management. |
| **Teacher** | Class-assigned attendance, continuous assessment entry, terminal grade posting, student notes. |
| **Parent / Student** | Read-only report card viewing, fee balance checks, online payment gateway checkout. |
